# 真实教材质量验收（2026-10-09）

本轮使用用户已导入的一本英文数学教材，经明确授权调用 `api.deepseek.com` 的 `deepseek-v4-pro`。原数据库只读打开，测试和迁移使用副本；完成后确认原数据库文件哈希未变化。教材原文、答案和数据库副本只保存在被 Git 忽略的 `data/evaluation/2026-10-09-baseline/`，不公开。

## 范围与方法

- 20 个自编问题：15 个英文、5 个中文；包含同书后部内容的检索。
- 从一个长章的开头、中间、末尾各取 1200 字符，生成 3 段简洁讲解。这是节选检查，不是整章覆盖率评测。
- 由本轮代码助手逐项核对答案与引用原文，以及讲解中的算例、维度、前提和题目选项；尚无独立教师评审。关键词命中只用作检索诊断，不当作正确率。
- 初次失败后，单独取得最多 5 次补测授权，实际使用 5 次：1 个失败问答、3 段讲解和 1 次 10 题生成。首次结果保留。

## 结果

| 项目 | 观察 |
| --- | --- |
| 首次问答 | 13/20 返回带引用答案，6/20 明确依据不足，1/20 生成失败 |
| 引用逐项核对 | 13 个带引用答案的主要结论由返回原文支持；样本以基础定义为主，不代表总体正确率 |
| 中文问英文教材 | 5/5 没有检索到原文，词项检索缺少跨语言能力 |
| 英文漏检 | 1 题未取到包含所需数值的片段；回答正确区分了补充解释与教材依据 |
| 失败问答补测 | 使用同一检索片段重试成功，恢复跨章引用；首次失败的具体原因未记录，不能确定归因 |
| 首次讲解 | 3/3 失败，未返回可验收讲解；原流程因此未出题 |
| 讲解补测 | 显式设置 `reasoning_effort=none` 后 3/3 成功，每次约 8–12 秒；内容质量仍有问题 |
| 10 道题 | 7 道按当前题面可用，3 道需要修订前提或维度；结构验证通过不等于教学质量合格 |

3 段讲解中：第 1 段基础定义和算例未发现主要错误；第 2 段外积更新算例中的数值与其写出的输入不一致；第 3 段把紧凑 QR 的矩阵写成了不兼容的维度，并在求解关系中缺少一致性／最小二乘条件。因此后两段不能直接当作可信讲义。

需修订的题目分别涉及：将零主元直接概括为 LU 不存在、未说明紧凑 QR 与最小二乘的前提，以及引用了维度不一致的数值例子。PDF 数学公式的文本提取包含拆散的符号与排列，也增加了模型误读风险；不能仅靠提示词或关闭思考修复数学正确性。

## 配置与复现

新增可选 `LLM_REASONING_EFFORT`，留空保留服务商默认值。DeepSeek V4 支持 `none/low/high/max`；本轮补测使用 `none`。该接口默认启用思考，参数说明见 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。首次讲解失败未采集返回原因，不能断言均由思考预算造成。

```powershell
apps/api/.venv/Scripts/python -B apps/api/evaluation/run.py --database apps/api/data/app.db --uploads apps/api/uploads --chapter-id 9 --output data/evaluation/new-run --live
```

这是会向配置的外部模型发送教材片段并产生费用的命令，运行前应确认教材许可与发送授权；输出目录必须是新的目录。题目在 `apps/api/evaluation/cases.json`，更换教材时也应更换案例。

下一阶段优先处理中文到英文的检索，再为数学讲解和题目增加公式维度、算例计算与条件完整性的检查。继续保留“不足即说明”的回答边界，不把结构合法当作质量合格。
